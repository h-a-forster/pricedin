# Data

`data/v1/` holds the frozen inputs and outputs of study v1. These files make it possible to
re-score the study with no network access:

```bash
uv run pricedin evaluate studies/v1.toml
```

Every file is JSON Lines (`.jsonl`, or gzip-compressed `.jsonl.gz`), one record per line. The
record types are defined in [`src/pricedin/schema.py`](../src/pricedin/schema.py). Times are
UTC ISO 8601 with a `Z` suffix. Probabilities are for the YES side.

| file | rows | content |
| --- | --- | --- |
| `candidates.jsonl.gz` | every eligible question | `Question` records before sampling |
| `sample.json` | 1 | counts per (venue, category): available vs sampled |
| `questions.jsonl` | the sample | `Question`: title, rules, times, outcome, fee terms |
| `snapshots.jsonl` | question × horizon | `Snapshot`: market mid (and bid/ask on Kalshi) at `as_of` |
| `snapshots_missing.json` | question × horizon | why a snapshot does not exist |
| `news.jsonl.gz` | question × horizon | `NewsContext`: items public before `as_of` |
| `forecasts/<forecaster>__<condition>.jsonl.gz` | question × horizon | `Forecast`: probability, short rationale, tokens, cost |

## Key fields

- **`Question.close_at`**: the anchor for horizons. It is the deadline that was known when
  the market was listed:
  - Polymarket: `endDate`.
  - Kalshi: `expected_expiration_time` minus a per-series settlement buffer. The buffer is
    the 10th percentile of the gap between expected expiration and close, over markets in
    that series that closed in the 180 days before the question was listed (at least 3, else
    0). A low quantile, because an early close only ever widens the gap. The estimate is not
    shown to the model; the rules text states the deadline.

  It is never the actual close. An early close, such as a "by <date>" market resolving YES,
  depends on the outcome.
- **`Question.extra.actual_close`**: when trading stopped. Train/test splits use this time,
  because the outcome was known from then on.
- **`Snapshot.as_of`**: `close_at` minus the horizon (7 days, 1 day or 1 hour). There is no
  row if the market had already closed by then, which is the same thing a real-time observer
  would see.
- **`Snapshot.mid`**: the last observation at or before `as_of`, and at most 6 hours old.
  - Kalshi: the mid of the 1-minute candle's best bid and ask, falling back to the last
    trade.
  - Polymarket: the CLOB price history; a point counts only if it is at least 60 s before
    `as_of`.
- **`NewsItem.seen_at`**: the timestamp of the Wikipedia revision the item was read from. It
  is never later than `as_of`, and the collector refuses to write a row that breaks this.
- **`Forecast.prob`**: `null` when the reply could not be parsed. Those rows are dropped and
  counted in the evaluation.

## Sources and licences

- **Market data**: the public Kalshi Trade API v2 and the Polymarket Gamma and CLOB APIs,
  collected 2026-10-10. It is used here for research; check each venue's terms before
  redistributing it in bulk.
- **News**: Wikipedia "Portal:Current events" daily pages, under CC BY-SA 4.0.
  - Each item links to the exact revision it was read from (`oldid`).
- **Forecasts**: generated by the models named in each file. Rationales are truncated to 600
  characters.

## Rebuilding from scratch

```bash
uv run pricedin collect studies/v1.toml     # ~1 h, mostly the Kalshi series scan
uv run pricedin snapshots studies/v1.toml
uv run pricedin news studies/v1.toml
uv run pricedin forecast studies/v1.toml -f claude-cli:claude-opus-5-5@low -c base
```

Venue data changes over time. For example, Kalshi moves settled markets to a separate
historical tier. A rebuild can therefore differ slightly from the frozen files. HTTP
responses are cached under `.pricedin-cache/`, so a re-run on the same machine sends no
requests.
